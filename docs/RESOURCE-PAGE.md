## Краткое описание

> Спавнеры, которые не создают мобов. Лут считается математически и сразу попадает на виртуальный склад — ни сущностей, ни предметов на земле, ни воронок под фермой. Стак из 10 000 спавнеров стоит серверу столько же, сколько один. Бесплатно, с открытым исходным кодом.

**Сокращённый вариант (для поля «tagline»):**

> Виртуальные стакающиеся спавнеры: ноль сущностей, ноль воронок, ноль лагов.

## Описание

### Проблема

На BoxPVP спавнеры — это вся экономика. И они же — источник лагов номер один.

Обычная ферма работает так:

```
спавнер тикает → создаёт мобов (Entity) → мобы тикают, ищут путь, толкаются
   → умирают → роняют предметы (снова Entity) → воронка засасывает (снова тики)
```

Пятьсот спавнеров в приватах, помноженные на эту цепочку, — это 8 TPS и «сервер лагает» в чате каждые пять минут.

### Решение

SNSpawners вырезает цепочку целиком. Ванильный спавн глушится, а лут **рассчитывается математически** и складывается в виртуальный склад спавнера. Игрок забирает его из меню или включает автовыгрузку в привязанный сундук.

Мобов нет. Предметов на земле нет. Воронки под фермой не нужны.

### Чем отличается от бесплатных стакеров

Стакеры вроде WildStacker или RoseStacker уменьшают **количество** сущностей: вместо 200 зомби — один со счётчиком. Это помогает, но сущности остаются: они тикают, их надо убивать, лут всё равно падает на землю.

Режим «спавнер вообще не спавнит мобов, а сразу выдаёт лут по вероятностям» до сих пор встречается только в платных плагинах. Здесь он есть, и он бесплатный.

### Главное инженерное решение

Наивная реализация стакающихся спавнеров бросает кубик на каждого моба. Стак из 2048 спавнеров × 4 моба за цикл × 180 пропущенных циклов = **1.5 миллиона бросков** на один спавнер при загрузке чанка. Это и есть тот фриз, за который ругают стакеры.

SNSpawners не перебирает — он берёт выборку из распределения целиком:

| величина | распределение |
|---|---|
| сколько раз выпал предмет | биномиальное `B(n, p)` |
| сколько всего штук | сумма `n` равномерных величин |

Пока попыток мало (по умолчанию до 64) — считается честным перебором, результат математически неотличим от ванильного. Выше порога включается аппроксимация: нормальная при большом среднем, пуассоновская при редких событиях.

**Замер на реальном коде** (200 000 вызовов, прогретый JIT):

```
стак ×1        (n = 1 000)         29 нс на вызов
стак ×100 000  (n = 100 000 000)   29 нс на вызов
```

**Точность** — отклонение среднего от теоретического:

```
n=1e6  p=0.025       среднее 24999.6   ожидалось 25000   отклонение 0.002 %
n=1e6  p=0.000005    среднее 4.98      ожидалось 5       отклонение 0.5 %
n=32   p=0.5         среднее 15.99     ожидалось 16      отклонение 0.085 %
```

### Что ещё сделано ради производительности

- **Производство ленивое.** Спавнер не тикает вообще. Он помнит момент последнего расчёта, и догон считается одной формулой — час простоя или месяц стоят одинаково.
- **Жёсткий тик-бюджет.** Обход идёт кольцевым курсором по плоскому массиву: `max-per-tick` спавнеров за запуск, остальные достанутся следующему. Время одного тика **не зависит** от количества спавнеров на сервере — растёт только время полного круга.
- **Удаление за O(1)** — перестановка с последним элементом, без сдвига хвоста.
- **Данные лежат в блоке** (`PersistentDataContainer`), внешней базы нет: ни I/O при выключении, ни миграций, ничего не разъезжается при откате бэкапа мира.
- **Компактный склад.** Ванильный дроп не имеет NBT, поэтому склад хранится строкой `id=количество`, а не Base64 от сериализованного инвентаря — в десятки раз меньше и быстрее. В памяти это `long[]` по индексу записи лута, без карт и упакованных `Long`.
- **Выгрузка пачками.** Перекладывание склада в сундук идёт по интервалу (`auto-flush.interval`), а забитый контейнер откладывается надолго (`retry-when-full`) — производство ленивое, накопленное уходит одним движением.
- **Голограммы на `TextDisplay`** — без ИИ и физики, помечены непостоянными: в файл чанка не пишутся. Уцелевшие после нештатного выключения подбираются по метке, а не дублируются. Текст пересобирается только при реальном изменении — сравнивается хэш, а не строки.

### Возможности

- **Стакинг** с автослиянием при установке рядом; лимит стака выдаётся правом `snspawners.stack.<число>`
- **Виртуальный склад** с вместимостью по уровню и настраиваемым поведением при переполнении: `STOP` / `VOID` / `REPLACE`
- **Оффлайн-накопление** с потолком — защита от «выключил сервер на месяц»
- **5 уровней улучшений**: скорость, удача (аналог Looting), вместимость склада
- **Автовыгрузка** в привязанный сундук, бочку или шалкер
- **Автопродажа** — лут сразу в деньги, с настраиваемой комиссией сервера
- **Три GUI-меню**: спавнер, постраничный склад, лестница улучшений — всё редактируется в `gui.yml`
- **Голограммы** над спавнером с произвольными строками
- **Защита**: только владелец, иммунитет к взрывам и поршням, чёрный список миров
- **HEX и градиенты** во всех текстах
- **Каждое сообщение настраивается отдельно**: канал доставки (чат / actionbar / титры), префикс, звук, тайминги

### Цвета

Работает всё сразу, в любом файле:

```yaml
text: "&aстарые коды &lи жирный"
text: "<#FF5C5C>HEX &#FF5C5C так тоже #FF5C5C и так"
text: "<gradient:#00E1FF:#7B2FFF>плавный переход</gradient>"
text: "<gradient:#FF0000:#00FF00:#0000FF>сколько угодно опорных точек</gradient>"
```

### Настройка одного сообщения

```yaml
messages:
  collect-success:
    type: ACTIONBAR          # CHAT | ACTIONBAR | TITLE | NONE — NONE отключает
    prefix: true             # подставлять общий префикс (только для CHAT)
    text: "<#5AFF8A>Получено <#FFFFFF>%items%"
    sound: "ENTITY_ITEM_PICKUP:0.7:1.2"
```

Короткая форма тоже работает: `collect-success: "&aПолучено %items%"`.

### Добавить свой тип спавнера

```yaml
types:
  DROWNED:
    display: "<gradient:#4FD1C5:#1F7A72>Утопленник</gradient>"
    icon: DROWNED_SPAWN_EGG
    period: 22          # секунд на цикл для одного спавнера
    per-cycle: 4        # мобов за цикл
    xp: [ 5, 5 ]
    price: 180000
    loot:
      flesh:
        item: ROTTEN_FLESH
        amount: [ 0, 2 ]
        chance: 1.0
        price: 0.4
      trident:
        item: TRIDENT
        amount: [ 1, 1 ]
        chance: 0.00085
        price: 5000.0
        affected-by-fortune: false
```

### Файлы конфигурации

| файл | что настраивает |
|---|---|
| `config.yml` | производительность, стакинг, защита, склад, голограммы, звуки |
| `spawners.yml` | 16 типов мобов с таблицами лута и ценами, 5 уровней улучшений |
| `messages.yml` | 45 сообщений — каждое со своим каналом, префиксом и звуком |
| `gui.yml` | все предметы всех меню: слоты, материалы, имена, описания |

### Как играется

1. Игрок ставит спавнер. Рядом ставит второй такой же — они **сливаются в стак**.
2. Спавнер не спавнит мобов, а копит лут на виртуальном складе.
3. ПКМ по спавнеру открывает меню: забрать всё, посмотреть склад, продать, улучшить.
4. Привязал сундук — лут перекладывается туда сам.
5. Включил автопродажу — лут превращается в деньги, минуя склад.
6. Shift + сломать снимает весь стак одним предметом.

## Зависимости

**Обязательных нет.** Плагин самодостаточен: ни одной библиотеки внутри, ни одного хард-депенда снаружи.

| зависимость | обязательность | что даёт |
|---|---|---|
| **Vault** + любой экономический плагин | опционально | продажу склада, автопродажу и покупку улучшений |

Без Vault плагин работает полностью — просто прячет из меню кнопки «Продать», «Улучшения» и переключатель автопродажи.

**Совместимость:**

- Работает поверх любых плагинов приватов (WorldGuard, GriefPrevention, ASkyBlock и прочих): обработчики стоят на `HIGHEST` с `ignoreCancelled`, поэтому отмена защитой срабатывает раньше.
- Не конфликтует со стакерами сущностей — мобов просто нет.
- Ванильные спавнеры из подземелий подхватываются при первом взаимодействии (отключается в `stacking.adopt-natural-spawners`).

## Команды и права

### Команды

Основная команда: `/snspawners`. Алиасы: `/snsp`, `/spawners`.

| команда | описание | право |
|---|---|---|
| `/snsp help` | список команд | — |
| `/snsp give <игрок> <тип> [кол-во] [стак]` | выдать спавнеры игроку | `snspawners.command.give` |
| `/snsp info` | статистика и реальное время обхода в мс | `snspawners.command.info` |
| `/snsp types` | список доступных типов | — |
| `/snsp reload` | перезагрузить все конфиги без рестарта | `snspawners.command.reload` |

У всех аргументов работает автодополнение по Tab.

### Права

| право | по умолчанию | что даёт |
|---|---|---|
| `snspawners.use` | все | открывать меню своих спавнеров |
| `snspawners.place` | все | ставить спавнеры |
| `snspawners.stack.<число>` | — | персональный лимит стака; берётся максимальное из выданных, но не выше `stacking.max-stack` |
| `snspawners.autosell` | — | доступ к переключателю автопродажи |
| `snspawners.bypass` | оператор | обход проверки владельца спавнера |
| `snspawners.command.give` | оператор | выдача спавнеров |
| `snspawners.command.info` | оператор | просмотр статистики |
| `snspawners.command.reload` | оператор | перезагрузка конфигов |
| `snspawners.admin` | оператор | всё вышеперечисленное сразу |

### Пример настройки донат-групп

```yaml
groups:
  default:
    permissions:
      - snspawners.stack.32
  vip:
    permissions:
      - snspawners.stack.128
      - snspawners.autosell
  premium:
    permissions:
      - snspawners.stack.512
      - snspawners.autosell
```

## Установка

1. Скачай `SNSpawners-1.0.0.jar`
2. Положи в папку `plugins/`
3. Перезапусти сервер
4. При желании поставь Vault и любой экономический плагин

Конфиги создадутся сами при первом запуске.
