# SNSpawners

**Виртуальные стакающиеся спавнеры для Paper 1.21.x. Ноль сущностей, ноль воронок, ноль лагов.**

Бесплатно, открытый исходный код, MIT. Без обфускации, без «премиум-версии», без телеметрии.

Автор — **Somikyy** · [t.me/somikyy](https://t.me/somikyy) · разработка плагинов и 3D-моделей.

---

## Зачем это нужно

На BoxPVP спавнеры — это вся экономика. И они же — источник лагов номер один.

Обычная ферма работает так: спавнер тикает → создаёт мобов (Entity) → мобы тикают, ищут путь, толкаются → умирают → роняют предметы (снова Entity) → предметы засасывает воронка (снова тики). Пятьсот спавнеров в приватах, помноженные на эту цепочку, — это 8 TPS и «сервер лагает» в чате.

SNSpawners вырезает цепочку целиком. Ванильный спавн выключается, а лут **рассчитывается математически** и складывается в виртуальный склад спавнера. Игрок забирает его из меню или включает автовыгрузку в привязанный сундук.

Мобов нет. Предметов на земле нет. Воронок под фермой не нужно.

## Чем отличается от бесплатных стакеров

Стакеры вроде WildStacker или RoseStacker уменьшают **количество** сущностей — вместо 200 зомби один со счётчиком. Это помогает, но сущности остаются: они тикают, их надо убивать, лут всё равно падает на землю.

Режим «спавнер вообще не спавнит мобов, а сразу выдаёт лут по вероятностям» до сих пор встречается только в платных плагинах. Здесь он есть, и он бесплатный.

## Главное инженерное решение

Наивная реализация стакающихся спавнеров бросает кубик на каждого моба. Стак из 2048 спавнеров × 4 моба за цикл × 180 пропущенных циклов = **1.5 миллиона бросков** на один спавнер при загрузке чанка. Это и есть тот фриз, за который ругают стакеры.

SNSpawners не перебирает. Он берёт выборку из распределения целиком:

| величина | распределение |
|---|---|
| сколько раз выпал предмет | биномиальное `B(n, p)` |
| сколько всего штук | сумма `n` равномерных величин |

Пока попыток мало (по умолчанию до 64), считается честным перебором — результат математически неотличим от ванильного. Выше порога включается аппроксимация: нормальная при большом среднем, пуассоновская при редких событиях.

Замер на реальном коде (`Rng.binomial`, 200 000 вызовов, прогретый JIT):

```
стак ×1        (n = 1 000)         29 нс на вызов
стак ×100 000  (n = 100 000 000)   29 нс на вызов
```

Отклонение среднего от теоретического — сотые доли процента:

```
n=1e6  p=0.025       среднее 24999.6  ожидалось 25000   отклонение 0.002%
n=1e6  p=0.000005    среднее 4.98     ожидалось 5       отклонение 0.5%
n=32   p=0.5         среднее 15.99    ожидалось 16      отклонение 0.085%
```

### Остальное про производительность

- **Ленивое производство.** Спавнер не тикает. Он помнит момент последнего расчёта, и догон считается одной формулой — час простоя или месяц стоят одинаково.
- **Жёсткий тик-бюджет.** Обход идёт кольцевым курсором по плоскому массиву: `max-per-tick` спавнеров за запуск, остальные достанутся следующему. Время одного тика **не зависит** от количества спавнеров на сервере — растёт только время полного круга.
- **Удаление за O(1).** Спавнер снимается с обхода перестановкой с последним элементом, без сдвига хвоста.
- **Данные в блоке.** Состояние живёт в `PersistentDataContainer` блока, а не во внешней базе: нет I/O при выключении, нет миграций, ничего не разъезжается при откате бэкапа мира.
- **Компактный склад.** Ванильный дроп не имеет NBT, поэтому склад хранится строкой `id=количество`, а не Base64 от сериализованного инвентаря — в десятки раз меньше и заметно быстрее при сохранении. В памяти это `long[]` по индексу записи лута: ни карты, ни упакованных `Long`, ни хэширования строк на каждый проход.
- **Выгрузка пачками.** Перекладывание склада в сундук — самая дорогая операция обхода, поэтому она идёт по интервалу (`auto-flush.interval`), а забитый контейнер откладывается надолго (`retry-when-full`). Производство ленивое, ничего не теряется: накопленное уходит одним движением вместо двадцати попыток в секунду.
- **Голограммы на `TextDisplay`.** Без ИИ, без физики, помечены непостоянными: в файл чанка не пишутся. Уцелевшие после нештатного выключения подбираются по метке в PDC, а не дублируются; бесхозные подчищаются на старте. Текст пересобирается только при реальном изменении — сравнивается хэш, а не строки. Дальность видимости ограничена (`view-range`), яркость фиксирована — клиент не сэмплит освещение под каждой строкой.
- **FPS игроков, а не только TPS сервера.** Клетка спавнера для клиента всегда «неактивна»: ни частиц огня и дыма, ни вращения — ванильная анимация на поле из сотни спавнеров съедает половину кадров. Модель моба внутри клетки по умолчанию не рисуется вовсе (`visual.mob-in-spawner`): клиент отрисовывает её каждый кадр для каждой клетки в поле зрения, а тип и так виден на голограмме. Спавнеры, поставленные старыми версиями или переписанные другими плагинами, приводятся к норме при загрузке чанка, и исправление досылается тем, кто уже смотрит на чанк.
- **Деньги пачками.** Выручка автопродажи копится в памяти и уходит в Vault одной операцией на владельца раз в `deposit-interval`, а не сотнями микро-депозитов в секунду. Перед открытием меню и покупкой улучшения очередь зачисляется досрочно.
- **Ноль зависимостей.** Vault — мягкая привязка: без него просто прячутся кнопки продажи и улучшений.

## Возможности

- **Стакинг** с автослиянием при установке рядом, лимит через право `snspawners.stack.<число>`
- **Виртуальный склад** с вместимостью, зависящей от уровня, и поведением при переполнении (`STOP` / `VOID` / `REPLACE`)
- **Оффлайн-накопление** с настраиваемым потолком — защита от «выключил сервер на месяц»
- **5 уровней улучшений**: скорость, удача (аналог Looting), вместимость склада
- **Автовыгрузка** в привязанный сундук, бочку или шалкер
- **Автопродажа** — лут сразу в деньги, с настраиваемой комиссией сервера
- **GUI** из трёх меню: спавнер, постраничный склад, лестница улучшений — всё редактируется в `gui.yml`
- **Голограммы** над спавнером с любыми строками
- **Защита**: только владелец, иммунитет к взрывам и поршням, чёрный список миров
- **HEX и градиенты** во всех текстах
- **Отдельная настройка каждого сообщения**: канал (чат / actionbar / титры), префикс, звук, тайминги

## Установка

1. Скачай `SNSpawners-1.0.0.jar` из [релизов](https://github.com/ASNETplugins/SNSpawners/releases)
2. Положи в `plugins/`
3. Перезапусти сервер
4. При желании поставь Vault + любой экономический плагин

**Требования:** Paper 1.21+ (или форк: Purpur, Pufferfish), Java 21.
Spigot не поддерживается — используются Adventure и Display-сущности.

## Файлы конфигурации

| файл | что настраивает |
|---|---|
| `config.yml` | производительность, стакинг, защита, склад, голограммы, звуки |
| `spawners.yml` | типы мобов, таблицы лута с ценами, уровни улучшений |
| `messages.yml` | каждое сообщение отдельно: текст, канал доставки, префикс, звук |
| `gui.yml` | все предметы всех меню: слоты, материалы, имена, описания |

### Цвета

Работает всё сразу, в любом файле:

```yaml
text: "&aстарые коды &lи жирный"
text: "<#FF5C5C>HEX &#FF5C5C так тоже #FF5C5C и так"
text: "<gradient:#00E1FF:#7B2FFF>плавный переход</gradient>"
text: "<gradient:#FF0000:#00FF00:#0000FF>сколько угодно точек</gradient>"
```

Закрывающий тег `</#RRGGBB>` необязателен и просто игнорируется.

### Настройка одного сообщения

```yaml
messages:
  collect-success:
    type: ACTIONBAR          # CHAT | ACTIONBAR | TITLE | NONE — NONE отключает
    prefix: true             # подставлять общий префикс (только для CHAT)
    text: "<#5AFF8A>Получено <#FFFFFF>%items%"
    sound: "ENTITY_ITEM_PICKUP:0.7:1.2"
```

Короткая форма тоже работает: `collect-success: "&aПолучено %items%"`.

### Новый тип спавнера

```yaml
types:
  DROWNED:
    display: "<gradient:#4FD1C5:#1F7A72>Утопленник</gradient>"
    icon: DROWNED_SPAWN_EGG
    period: 22          # секунд на цикл для одного спавнера
    per-cycle: 4        # мобов за цикл
    xp: [ 5, 5 ]
    price: 180000
    loot:
      flesh:
        item: ROTTEN_FLESH
        amount: [ 0, 2 ]
        chance: 1.0
        price: 0.4
      trident:
        item: TRIDENT
        amount: [ 1, 1 ]
        chance: 0.00085
        price: 5000.0
        affected-by-fortune: false
```

## Команды

| команда | описание | право |
|---|---|---|
| `/snsp help` | список команд | — |
| `/snsp give <игрок> <тип> [кол-во] [стак]` | выдать спавнеры | `snspawners.command.give` |
| `/snsp info` | статистика и реальное время обхода в мс | `snspawners.command.info` |
| `/snsp types` | доступные типы | — |
| `/snsp reload` | перезагрузить конфиги | `snspawners.command.reload` |

Алиасы: `/snspawners`, `/spawners`.

## Права

| право | по умолчанию | что даёт |
|---|---|---|
| `snspawners.use` | все | открывать меню своих спавнеров |
| `snspawners.place` | все | ставить спавнеры |
| `snspawners.stack.<число>` | — | персональный лимит стака (берётся максимальное выданное) |
| `snspawners.autosell` | — | доступ к переключателю автопродажи |
| `snspawners.bypass` | оператор | обход проверки владельца |
| `snspawners.admin` | оператор | всё вышеперечисленное |

Пример для донат-групп:

```yaml
groups:
  vip:
    permissions:
      - snspawners.stack.128
      - snspawners.autosell
  premium:
    permissions:
      - snspawners.stack.512
      - snspawners.autosell
```

## Как играется

1. Игрок ставит спавнер. Рядом ставит второй такой же — они **сливаются в стак**.
2. Спавнер не спавнит мобов. Он копит лут на виртуальном складе.
3. ПКМ по спавнеру открывает меню: забрать всё, посмотреть склад, продать, улучшить.
4. Привязка сундука — и лут перекладывается туда сам.
5. Автопродажа — и лут превращается в деньги, минуя склад.
6. Shift + сломать снимает весь стак одним предметом.

## Сборка из исходников

```bash
git clone https://github.com/ASNETplugins/SNSpawners.git && cd SNSpawners && mvn clean package
```

Готовый JAR появится в `target/SNSpawners-1.0.0.jar`. Нужен JDK 21.

## Совместимость

- Работает поверх любых плагинов приватов (WorldGuard, GriefPrevention, ASkyBlock и прочих) — обработчики стоят на `HIGHEST` с `ignoreCancelled`, поэтому отмена защитой срабатывает раньше.
- Не конфликтует со стакерами сущностей: мобов просто нет.
- Ванильные спавнеры из подземелий подхватываются при первом взаимодействии (отключается через `stacking.adopt-natural-spawners`).
